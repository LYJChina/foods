# 潮州市食品行业 AI 公共服务中台整体页面设计

## 1. 设计目标

将现有偏宣传展示的公共门户调整为面向政府和公共服务场景的 AI 服务中台。首页承担运行概况、服务数据和快捷分流；智能服务大厅承担服务发现；具体服务页面承担材料提交、任务处理和结果查看。

本次设计不新增 RAG 数据库、统计后台或 MCP 功能。首页统计数据一期使用前端样例数据，但通过稳定的数据访问接口读取，后续可无缝替换为真实后端接口。

## 2. 用户与使用场景

主要用户包括：

- 政府部门和项目建设方：查看平台运行概况和能力覆盖情况。
- 食品企业用户：寻找适合的公共 AI 服务并完成办理。
- 平台运营人员：了解服务使用情况和近期事项。

核心任务为：

1. 快速了解平台当前服务情况。
2. 找到适合自己的智能服务。
3. 进入具体服务页面提交材料并查看结果。
4. 从首页助手通过典型案例快速进入对应服务。

## 3. 信息架构

公共门户一级导航为：

1. 中台首页
2. 智能服务大厅
3. 办理记录
4. 使用指南

页面层级如下：

- 中台首页
  - 运行概况
  - 服务趋势
  - 智能服务使用分布
  - 最近办理事项
  - 公共服务助手
- 智能服务大厅
  - 全部服务
  - 文档与知识
  - 政策与合规
  - 企业服务
  - 诊断与评估
- 具体服务页面
  - 智能文档解析
  - 出口合规预检
  - 企业数智化诊断
  - 后续新增服务
- 办理记录
  - 事项列表
  - 状态筛选
  - 结果入口
- 使用指南
  - 平台能力说明
  - 数据安全边界
  - 常见问题

“智能体办理页面”仅作为设计阶段的页面类型，不作为用户可见名称。用户看到的是具体服务名称。

## 4. 视觉设计方向

采用“政府公共服务中台”方向，强调权威、秩序、清晰和信息效率，弱化 SaaS 宣传页式的大标题、渐变背景、悬浮卡片和营销语言。

视觉规则：

- 使用深蓝、白色、浅灰作为主要颜色，金色只用于导航分隔或少量重点状态。
- 大型容器、卡片、按钮和输入框采用直角或 2px 微圆角，不使用胶囊式组件。
- 不使用渐变背景、玻璃效果和大面积投影；通过边框、底色和间距建立层级。
- 页面正文不小于 16px，辅助信息不小于 13px，保证对比度和键盘焦点可见。
- 图标统一使用 Remix Icon，不使用表情符号。
- 未获授权时不使用国徽、政府机关徽标或仿造公章图形。
- 图表使用政务蓝、青绿和灰色，不采用紫粉色 AI 风格。

## 5. 中台首页

### 5.1 公共页头

公共页头采用三段式结构：

1. 顶部信息条：平台属性、使用帮助和数据安全入口。
2. 品牌区：平台名称及“服务食品产业数字化转型”说明。
3. 主导航：中台首页、智能服务大厅、办理记录、使用指南。

页面不展示 DEMO、原型或版本徽标。涉及样例统计时，仅在统计区域显示“示例数据”说明。

### 5.2 标题与运行状态

首页标题为“食品行业 AI 公共服务中台”，副标题说明平台汇集文档解析、政策合规辅助和企业数智化服务。标题右侧展示数据更新时间和系统运行状态，不使用整屏宣传式 Hero。

### 5.3 核心指标

首屏展示四个指标：

| 指标 | 一期样例值 | 接口字段 |
| --- | ---: | --- |
| 累计办理事项 | 1,286 件 | total_handled |
| RAG 知识库文档 | 3,642 份 | knowledge_documents |
| 今日服务人数 | 176 人 | today_users |
| 当前开放智能服务 | 4 个 | active_agents |

指标面板采用直角白色容器、细边框和深蓝顶部线。由于一期没有真实统计，不显示增长率、同比或排名，避免产生虚假统计含义。

### 5.4 可视化与助手

首页主体使用十二栏网格：

- 左侧八栏：近 7 日服务办理趋势和智能服务使用分布。
- 右侧四栏：公共服务助手。

趋势图默认使用柱线组合或折线图；服务分布采用横向条形图。支持“近 7 日 / 近 30 日”切换，但一期数据来自同一前端样例数据源。

公共服务助手一期定位为“服务导航助手”，不在缺少通用知识库时假装可以回答所有问题。助手包含欢迎语、文本输入、推荐服务和快捷案例：

- 帮我解析一份政策或业务文件。
- 帮我提炼文档重点和条款。
- 我想进行出口合规预检。
- 帮我判断企业适合哪些 AI 场景。

选择案例后，助手展示推荐服务、所需材料和“立即办理”按钮，再跳转到具体服务页面。文档上传仍在智能文档解析页面完成。

### 5.5 下半部分

首页下半部分包含：

- 最近办理事项：事项名称、使用服务、提交时间、状态和结果入口。
- 热门公共服务：展示三至四个常用服务入口。

一期使用样例事项时，在区域标题旁标注“示例数据”，不伪装成真实业务记录。

## 6. 智能服务大厅

页面名称使用“智能服务大厅”，避免在用户界面中反复使用技术化的“智能体”概念。

顶部包含页面标题、服务搜索和分类筛选。分类为：全部服务、文档与知识、政策与合规、企业服务、诊断与评估。

每张服务卡片展示：

- 服务分类和开放状态。
- 服务名称和简要说明。
- 服务方式和所需材料。
- “立即办理”或“规划中”状态。

一期服务建议如下：

| 服务 | 分类 | 状态 |
| --- | --- | --- |
| 智能文档解析 | 文档与知识 | 已开放 |
| 出口合规预检 | 政策与合规 | 已有基础规则流程 |
| 企业数智化诊断 | 诊断与评估 | 已有基础问卷流程 |
| AI 场景匹配 | 诊断与评估 | 由现有应用场景页面演进 |
| 政策文件解读 | 文档与知识 | 规划中 |
| 食品标签辅助检查 | 政策与合规 | 规划中 |
| 申报材料整理 | 企业服务 | 规划中 |

规划中的服务不可进入办理页，避免形成虚假可用入口。

## 7. 具体服务页面

具体服务直接使用业务名称，例如“智能文档解析”“出口合规预检”“企业数智化诊断”。统一页面结构为：

1. 面包屑、服务名称和边界说明。
2. 办理步骤与任务状态。
3. 左侧材料输入或上传区域。
4. 右侧服务说明和数据边界。
5. 处理结果、引用来源和后续操作。

智能文档解析继续使用现有链路：前端调用平台 FastAPI，平台后端调用 DocumentParser，解析结果由平台后端组织并交给后端配置的大模型完成带引用问答。

## 8. 样例数据与接口预留

前端新增统一的 Dashboard 数据访问层。页面组件不得直接导入散落的常量，而是调用与未来后端一致的方法：

| 方法 | 返回内容 |
| --- | --- |
| getDashboardSummary | 四项核心指标、更新时间和数据模式 |
| getServiceTrend | 日期序列和每日办理量 |
| getServiceDistribution | 服务名称、办理量和占比 |
| getRecentCases | 最近事项列表 |
| getQuickAssistantCases | 助手快捷案例和目标服务路由 |

一期由本地样例适配器实现以上方法，并返回 `data_mode` 为 `sample`。未来接入后端时只替换适配器实现，不修改图表、指标卡和表格组件。

预留后端路径建议为：

- `GET /food-ai/dashboard/summary`
- `GET /food-ai/dashboard/trend`
- `GET /food-ai/dashboard/distribution`
- `GET /food-ai/dashboard/recent-cases`

以上路径只是本项目拟采用的接口设计，并非现有政府网站接口。

## 9. 响应式规则

- 1440px：十二栏布局，图表八栏、助手四栏。
- 1024px：指标保持四列，助手与图表可调整为七栏和五栏。
- 768px：指标改为两列，助手移动到图表上方。
- 375px：全部单列，图表简化横轴标签，助手快捷案例改为纵向列表。

所有移动端操作目标不小于 44px，不产生横向滚动。

## 10. 一期范围与验收

一期包含：

- 重构公共页头、主导航和页脚。
- 建设中台首页数据总览、样例图表、近期事项和服务导航助手。
- 建设智能服务大厅及分类筛选。
- 将现有功能入口迁移到对应服务卡片。
- 保持智能文档解析现有后端链路不变。
- 建立 Dashboard 前端接口适配层。

一期不包含：

- 真实统计后台。
- RAG 知识库管理和数据库查询。
- 通用知识问答助手。
- MCP 和开放 API 管理。
- 未实现服务的虚假办理流程。

验收标准：

- 首页在 100% 浏览器缩放下完整展示核心指标和主要入口。
- 首页所有样例统计均有清晰但克制的样例标识。
- 智能服务大厅能够分类筛选，已开放服务可进入对应页面。
- 规划中服务不能误导用户进入空白流程。
- 375px、768px、1024px、1440px 均无横向滚动。
- 页面不使用明显圆角、渐变背景、浮夸阴影或未经授权的政府标识。
