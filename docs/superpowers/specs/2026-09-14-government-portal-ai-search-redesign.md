# 食品行业 AI 公共服务门户与智能问答重构设计

## 1. 目标与范围

本次重构把当前偏“运行看板”的首页调整为更接近政府公共服务门户的信息入口。首页负责找服务、看通知和进入智能问答；独立智能问答页负责连续对话、服务推荐和来源提示。

本期包含：

- 重构公共门户页头、首页和页脚。
- 首页增加 AI 搜索入口、快捷办理、服务专区、工作动态和通知公告。
- 新增独立的“公共服务智能问答”页面。
- AI 搜索框点击或提交后跳转智能问答页，并携带已输入的问题。
- 保留智能服务大厅、文档解析、出口预检、企业诊断、场景匹配、办理记录和使用指南。
- 新闻、通知和门户统计先使用明确标注的样例数据，并通过数据适配层保留后端接口位置。

本期不包含：

- 接入广州市政府网站的后台接口、新闻接口或数据库。
- 冒用政府机关名称、国徽、公章、官方 Logo 或认证标识。
- 实时法规库、通用 RAG 知识库、MCP 服务和正式业务审批。
- 在模型不可用时伪造真实问答结果。

## 2. 事实来源与设计边界

### 2.1 公开参考页面可观察内容

参考页面 `https://www.gz.gov.cn/zwfw/index.html` 的公开页面可观察到：

- 多层政府门户页头和横向主导航。
- 站内关键词搜索。
- “我要查”“我要办”“智能问答”等任务型入口。
- 个人、法人、特殊群体、部门等分类服务组织方式。
- 最新服务、新闻或政务信息列表。

参考页面 `https://www.gz.gov.cn/ghwd/znwd/index.html` 的公开页面可观察到：

- 智能问答使用独立页面承载。
- 页面提供欢迎语、热门问题、问答技巧、快捷服务和问题输入框。
- 用户从入口进入后再开始连续对话。

本设计只借鉴公开可见的信息架构和交互模式，不声称获得参考网站的接口、数据库结构、认证机制或内部实现。

### 2.2 本项目现有事实

- 公共门户使用 Vue 3、TypeScript、Vue Router 和 SCSS。
- 公共路由位于 `/portal`，现有首页、智能服务大厅、办理记录、使用指南和具体服务页面均为匿名公开路由。
- 智能文档解析已经具备前端、平台 FastAPI、独立文档解析服务和后端模型问答链路。
- 首页统计当前通过 `DashboardAPI` 返回样例数据。
- 智能服务目录已经通过统一的 `publicServices` 数据源维护。

### 2.3 合理推断

- 食品行业企业用户比平台运营人员更需要“搜索、找服务、看通知”，因此首页不再以运行指标和图表为视觉中心。
- 独立问答页需要复用现有后端模型配置，但必须使用新的公共助手 API 边界，不能从前端直接访问模型服务。
- 样例新闻与通知需要显式显示“示例信息”，避免被误认成真实政府公告。

## 3. 已确认的视觉方向

设计图：

- `docs/design/public-service-homepage.png`
- `docs/design/public-service-assistant.png`

视觉规则：

- 主色为政府深蓝 `#174B82`，功能蓝为 `#2F6FB2`，背景使用白色和浅灰蓝。
- 红色仅作为栏目标题下划线或少量当前导航提示，不作为大面积背景。
- 容器使用直角或 2px 微圆角；不使用胶囊卡片、大面积阴影、玻璃效果和紫色 AI 渐变。
- 页面信息密度高于当前首页，但通过标题、分隔线和栏栅保持秩序。
- 正文最小 14px，主要操作目标不小于 44px，键盘焦点清晰可见。
- 图标沿用项目现有 Iconify/Remix Icon，不使用表情符号和卡通机器人。
- 不使用未经授权的政府标志、国徽、公章或仿官方认证图形。

设计图是布局与视觉方向稿。实施时所有中文文字使用真实 HTML，保证准确、可访问和响应式，不直接把整张图片作为网页背景。

## 4. 新信息架构

一级导航调整为：

1. 首页
2. 智能服务
3. 办理记录
4. 使用指南

公共路由结构：

- `/portal/home`：政府公共服务门户首页。
- `/portal/services`：智能服务大厅。
- `/portal/assistant`：公共服务智能问答。
- `/portal/records`：办理记录。
- `/portal/guide`：使用指南。
- `/portal/documents`：智能文档解析。
- `/portal/precheck`：出口合规预检。
- `/portal/diagnosis`：企业数智化诊断。
- `/portal/scenarios`：AI 场景匹配。

“公共服务智能问答”是独立服务页，不再以内嵌右侧助手形式占用首页空间。

## 5. 首页设计

### 5.1 页头

页头分为三层：

1. 辅助栏：平台属性、无障碍入口、使用帮助。
2. 品牌栏：平台名称“食品行业 AI 公共服务平台”和克制的服务定位说明。
3. 主导航：首页、智能服务、办理记录、使用指南。

不使用城市政府名称和未经授权的官方标识。现有“潮州市”文案是否保留由建设方在上线前确认；未确认前统一使用中性的食品行业平台名称。

### 5.2 AI 搜索首屏

首页首屏以 AI 搜索为唯一主操作：

- 搜索框内显示 AI 助手图标和“AI 助手”标签。
- 输入提示为“请输入您想咨询或办理的事项”。
- 搜索按钮为深蓝色直角按钮。
- 下方展示四至六个热门问题或关键词。

交互规则：

- 点击空搜索框时跳转 `/portal/assistant`。
- 输入问题并提交时跳转 `/portal/assistant?q=<编码后的问题>`。
- 智能问答页读取 `q` 参数，将问题预填入输入框；模型服务可用时由用户点击发送，避免页面加载即产生模型费用。
- 键盘 Enter 与搜索按钮行为一致。
- 不在首页直接展示聊天消息、模型答案或浮动聊天气泡。

### 5.3 快捷入口

首屏下方设置四个任务型入口：

| 入口 | 目标 |
| --- | --- |
| 我要查 | 智能服务大厅并聚焦搜索框 |
| 我要办 | 智能服务大厅并优先显示可办理服务 |
| 智能问答 | 公共服务智能问答页 |
| 文档解析 | 智能文档解析页 |

### 5.4 服务专区

服务专区使用四列紧凑入口，不重复当前服务大厅的完整卡片信息：

- 政策与合规
- 企业服务
- 文档与知识
- 诊断与评估

每个入口展示分类名称、两至三个代表能力和统一箭头。点击后进入 `/portal/services?category=<categoryId>`，服务大厅读取参数并应用筛选。

### 5.5 工作动态与通知公告

首页下半部分使用两列信息列表：

- 左列“工作动态”：平台能力更新、培训活动、行业数字化服务动态。
- 右列“通知公告”：服务维护、材料要求、功能上线与使用提示。

每条信息包含标题、发布日期和类型。样例内容统一带 `data_mode: sample`，页面栏目标题旁显示“示例信息”。标题可以点击进入本地详情抽屉或占位详情页，但不得链接到不存在的真实政府公告。

建议数据接口：

- `PortalContentAPI.getNews()`
- `PortalContentAPI.getNotices()`

一期由前端样例适配器返回数据；未来替换为后端实现时保持页面组件不变。以上为本项目拟定接口，不是参考政府网站接口。

## 6. 公共服务智能问答页

### 6.1 页面结构

页面由以下部分组成：

- 面包屑和页面标题“公共服务智能问答”。
- 左侧辅助导航：常见问题、热门服务、问答技巧。
- 主对话区：欢迎语、快捷问题、对话消息、参考来源和输入区。
- 底部提示：“AI 生成，仅供辅助参考”。

移动端隐藏左侧栏，将三个入口改为顶部可横向滚动的标签。

### 6.2 快捷问题

首批快捷问题：

- 如何解析政策文件？
- 出口合规需要哪些材料？
- 如何开展企业数智化诊断？
- 怎样选择合适的 AI 场景？

点击快捷问题只填入输入框，不立即发送。

### 6.3 问答能力边界

新增后端边界建议：

- `POST /food-ai/assistant/questions`

请求字段：

- `question`：必填，1 至 2000 字符。
- `conversation_id`：可选，用于连续对话。

响应字段：

- `answer`：模型回答。
- `conversation_id`：会话标识。
- `recommended_services`：匹配到的服务名称和站内路由。
- `sources`：仅在存在可靠来源时返回；没有来源时为空数组。
- `disclaimer`：固定返回“AI 生成，仅供辅助参考”。

后端使用环境变量中的模型地址、模型名称和 API key。前端只调用平台 FastAPI，不读取、存储或显示 API key。超时建议 30 秒；网络失败和模型未配置时返回明确的 503 提示，不使用假答案兜底。

在没有正式政策知识库时，公共助手只承担：

- 平台服务导航。
- 已公开、已配置材料范围内的常识性解释。
- 将复杂问题引导到文档解析、出口预检、企业诊断等具体服务。

它不得声称提供正式审批、认证、监管或法律结论。

## 7. 数据与状态设计

新增前端模块建议：

- `api/module_food_ai/content.ts`：新闻、通知样例适配器。
- `api/module_food_ai/assistant.ts`：智能问答 API。
- `views/portal/home/index.vue`：门户首页。
- `views/portal/assistant/index.vue`：独立问答页。
- `views/portal/assistant/components/`：侧栏、快捷问题、消息列表、输入区。

问答页状态：

- `idle`：欢迎页和快捷问题。
- `submitting`：显示发送中并禁用重复提交。
- `answered`：展示回答、来源和推荐服务。
- `unavailable`：模型未配置或服务不可用，保留用户问题并提供重试。

新闻与通知状态：

- 加载中使用固定高度骨架，避免布局跳动。
- 空数据时显示“暂无信息”，不留空白区域。
- 加载失败显示局部错误和重试，不影响首页服务入口。

## 8. 响应式与可访问性

- 1440px：完整页头、四列快捷入口、四列服务专区、新闻通知双列。
- 1024px：快捷入口保持四列，服务专区改为两列。
- 768px：品牌栏压缩，导航可换行，新闻通知改单列。
- 375px：所有服务入口改单列或两列，AI 搜索按钮保持 44px，页面无横向滚动。
- 搜索、导航、标签和发送按钮具备可见焦点态。
- 对话新增消息使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 状态不能只依赖颜色表达；图标旁必须有文字。
- 尊重 `prefers-reduced-motion`，不使用大幅进入动画。

## 9. 现有页面处理

- 首页原有运行指标、趋势图、服务分布和最近办理事项移出门户首页。
- 办理数据仍可保留在 `/portal/records`，后续如需要运营看板可另设登录后管理页面。
- 智能服务大厅继续保留筛选和搜索，并增加 URL 分类参数同步。
- 文档解析、出口预检、企业诊断和场景匹配的业务流程不改，仅统一页头、标题和视觉 token。
- 删除或停用旧的首页内嵌助手组件，避免出现两个不同的问答入口。

## 10. 验收标准

- 首页结构与确认的首页设计图一致，并在首屏突出 AI 搜索。
- AI 搜索空点击和带问题提交均能进入 `/portal/assistant`。
- 智能问答页能读取查询参数、展示快捷问题、发送问题并处理成功、失败和未配置状态。
- 新闻与通知均明确标注为样例信息，不伪装成真实政府发布。
- 四个快捷入口和四个服务分类均有有效站内路由。
- 页面不出现未经授权的政府标识，不声称使用参考网站内部接口。
- API key 不进入前端代码、构建产物、截图、日志或 Git 仓库。
- 前端类型检查、单元测试和开发构建通过。
- 后端问答接口测试覆盖正常、超时、模型未配置和无可靠来源场景。
- 375px、768px、1024px、1440px 无横向滚动，键盘可完成搜索与问答。
